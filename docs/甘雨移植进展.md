填 `ATLAS_NAME` 时若漏了这一层，贴图会被当成两个材质各编一份，浪费一半显存。

### 1.2 按材质分 head / torso，不按高度分

`发` 的几何从 y = 19.91（发顶）一直挂到 **y = 10.25**（腰），按高度切会把长发
劈成两半、把下半截塞进 torso。它的权重是 `頭` + `发_*_*` 链（折叠到 `Bip01 Head`），
所以必须整块跟着头走。**按材质分**天然解决这个问题。

## §2 判据测量（都是量出来的）

`tools/check_winding.py`、`tools/measure_ganyu_geometry.py`、
`tools/diag_ganyu_overlays.py`、`tools/diag_ganyu_alpha_faces.py`。

### 2.1 坐标手性：与荧完全一致

```
左目   − 頭        = (+0.47, +0.62, −0.71)    眼睛在 −Z
左足先EX − 左足首D  = (+0.14, −0.58, −0.96)    脚尖在 −Z
→ −Z 是「前」，映射 (x, y, z) → (x, −z, y)，det(R) = +1.0000
```

绕序判据（PMX 自带顶点法线 vs 几何面法线）：
`mean dot = +0.959，positive = 0.997` → **源绕序与右手法则一致，保持不翻转**。
翻转的对照数据也在同一份输出里（det = −1 的候选映射给出 `mean = −0.959`）。

### 2.2 UV 的 v 轴：同样的三层约定

PMX 的 v 向上还是向下、Blender 与导出器各翻一次 —— 与荧完全同源，所以
`stage1` 里 `v_blender = 1 − v_pmx` 的处理照搬，并用同一套可复现验证链
（源 skin v 区间 → 期望 stage 值 → 导入成品 xac 后读回）核对。

### 2.3 骨架拟合

| 项 | 值 | 对照（荧） |
|---|---|---|
| scale | **9.6267 cm/unit** | 9.7746 |
| det(R) | **+1.0000** | +1.0000 |
| 带权骨 → 映射 | **187 → 53 直接 + 134 折叠 + 0 未映射** | 210 → 53 + 157 + 0 |
| 残差（对齐骨） | mean 6.6 cm，max 13.6 cm（`左足首D`） | 脚踝 13.5 / 髋 8.4 / 手肘 7.7 |

残差分布几乎一样 —— 两个模型都是原神 MMD 骨架，比例接近。
`上半身3`（636 顶点）按链根折叠到 `上半身` → `Bip01 Spine1`，与荧一致
（**一个 X4 骨只能有一个直接驱动者**，这条规则两边都踩过）。

### 2.4 腿：横向阻尼沿用 0.60 / 0.85 / 0.95，实测验证

| X4 骨 | 源拟合 X | 该骨驱动的几何 X | 阻尼后目标 X | X4 bind X |
|---|---|---|---|---|
| `Bip01 L Thigh` | 9.22 | 8.84 | **10.66** | 11.61 |
| `Bip01 L Calf` | 7.64 | 6.80 | **13.73** | 14.81 |
| `Bip01 L Foot` | 5.89 | 6.80 | **17.11** | 17.70 |
| `Bip01 L Toe0` | 7.27 | 8.24 | **20.78** | 21.50 |

判据两条，都过：

* **骨链横向单调外撇**（10.66 → 13.73 → 17.11）—— 逐级递减会把骨链折弯，
  关节落到它驱动的几何内侧，这才是"猫步"的根因；
* **两脚间距**：几何量 36.3 cm，vanilla 女性 39.8 cm（0.91×），X4 bind 35.4 cm。

### 2.5 颈部与脚底

* `上半身2` 与 `首/頭` 的**混合带**实测在 **z 146.6 – 154.2 cm**（|x| < 7，494 顶点），
  所以 `NECK_FIX_Z = (145, 157)` 覆盖得住（只重绑 |x| < 7 cm 的中线带，
  碰不到肩膀）。实测重绑 1032 个顶点。
* 脚底：retarget 后最低点在 **z = +0.76 cm**（悬空），`GROUND_Z = −0.5`
  → 下沉 **1.26 cm** 落地。

## §3 三个"必须做决定"的地方

### 3.1 `脸红`（blush）丢弃 —— 证据

`表情.png` 是 4096²，**整图 alpha ≤ 66**（>128 的比例 0.0%），
而 `脸红` 自己的 UV 采样出来 **中位 alpha = 0**。这是一个只靠表情 morph 抬起来的
淡腮红贴花，NPC 永远不播表情。

留着它意味着：① 它在脸上浮 3 mm 与 `face` 并存（重合风险）；
② 只能靠 `ALPHA8`（8 位 alpha 混合）才看得见 alpha 0.26 的东西，而那要一张 BC3
贴图加一个混合层。**丢弃**，理由与数据写进 `ganyu_src.DROP_STEMS`。

### 3.2 删除作者的"隐藏面" —— 这是本工程最关键的一步

`diag_alpha_faces.py` 报 `cloth` 9.1%、`skin` 7.9% 的三角面**整面采样到 alpha 0**。
渲染出来看（`diag_ganyu_alpha_faces.py` 会把两组分开渲染）：

* `cloth` 的 906 面是**胸衣内衬**（被外层挡住的部分）；
* `skin` 的 86 面是**被衣服盖住的身体**（胸口一块菱形 + 腋下两块）。

作者用"涂成全透明"来删面。**我们直接删三角形，完全等价，而且省几何。**

**为什么必须删而不是留着用 alpha 模式**：X4 的 `blendmode` 是**单值**
（`NONE` / `ALPHA1` / `ALPHA8` / `TWOSIDED` / …，实测 vanilla 取值表里没有组合）。
`cloth` 是单层薄片（裙摆、袖子），背面必须能看见 → 必须 `TWOSIDED`；
而 `TWOSIDED` 不读 alpha。所以"双面 + alpha 测试"在 X4 里做不到，
只能把不可见的面删干净，让剩下的面全都不透明。

判据阈值 `ALPHA_KEEP = 0.03` 由 `ganyu_src.sample_face_alpha()` 统一定义，
**stage1 与诊断脚本共用同一个函数**（诊断自己发明一套采样，荧的项目已经吃过一次亏）。
实测删掉 **992 面**（906 + 86），与诊断的预期完全吻合。

### 3.3 重合层推开

| 对 | 重合程度 | 处理 |
|---|---|---|
| `cloth` ↔ `skin` | **skin 的 766 个顶点 100% 在 1 mm 内**（最小 0.00） | 整件服装（cloth+skirt+extra+waist）沿法线推 **2.0 mm** |
| `face2` ↔ `face` | 中位 0.4 mm，68% 在 1 mm 内 | `face2` 推 **1.5 mm** |
| `vision` ↔ `waist` | 中位 1.5 mm，50% 在 1 mm 内 | `vision` 再推 **1.5 mm** |
| `skirt` / `extra` ↔ `cloth` | 只在接缝处 | **跟着一起推**，否则接缝会裂开 2 mm |

同一深度的两层在引擎的深度缓冲里会打架，实机表现为闪烁的色块
（荧之前的"黑丝袜闪烁"就是这个）。推开是唯一稳妥的修法。

## §6 踩过的坑（都是会静默出错的类型）

### 6.1 argon 的 macro 清单结构与 terran 不同 → 会静默替换 0 个 macro

`find_female_macros.py` 写过两种格式：terran 那次是**纯名字列表**，
argon 这次是**带证据的 dict**（`{targets:[{name, why, types}], skipped, mismatch}`）。

`make_mod.py --mode replace` 原本直接 `json.load()` 后 `for name in macros` ——
对 dict 迭代得到的是键名 `['race','targets',...]`，生成的 XML 里会有 5 条
指向不存在 macro 的 `<replace>`：**mod 能装、能加载、什么都不改，且不报错**。
现在统一走 `load_macro_list()`，并在结果为空时硬失败。

### 6.2 `diag_normals.py` 的 smoothness 结论写反了

那个脚本（继承自荧）打印 `mean corner-normal spread 0.0000  (0 = flat, ...)`。
**实际是反的**：`mesh.loops[i].normal` 在平滑着色下返回**顶点法线**（同一顶点所有
loop 相同 → spread = 0），在平面着色下返回**面法线**（不同面不同 → spread > 0）。
所以 `0.0000` 意味着**平滑**，是正确的。

我按那句注释去查了一轮"为什么全是平面着色"，并用荧的 stage1 做对照
（同样 0.0000）才确认注释错了。已修正注释与判据文字。

顺带说明 `report.json` 里 `normals` 指标（`mean|dot(面法线,顶点法线)|`）：
甘雨 0.987 / 荧 0.990 / vanilla 0.945 —— **不是"甘雨更平面"**，
而是网格越密、相邻面夹角越小，平均法线就越贴近每个面。两个 mod 同量级即为正常。

### 6.3 `build_all.py` 默认会安装到游戏

从 BoRu 工程继承的 `build_all.py` 把 `deploy` 放进了 `STEPS`，于是
"构建"默认就是"构建 + 安装到 `X4 Foundations/extensions/`"。
我这边因此**意外安装了 add 版**（可用 `deploy.py --mode none` 卸载）。
已改：`deploy` 只由 `--deploy` 触发。

### 6.4 中文贴图名必须有显式映射

`prepare_textures_*.py` 的 `atlas_stem()` 在拿不到映射时会剥掉非 ASCII 字符，
剥完是空串就 `raise SystemExit`。荧的 `颜.png/髪.png/衣.png` 与甘雨的
`面.png/发.png/服.png/肌.png/表情.png` 完全不同，必须补 `ATLAS_NAME`，
否则贴图步骤直接死掉（这个失败是响亮的，比静默好）。

### 6.5 复制工具链时的路径替换要验算层级

把荧的工具链整目录拷过来做 `sed`（`lumine` → `ganyu`）之后，我又批量把硬编码的
`D:\dsh-x4\...` 换成 `os.path.dirname(...)` 表达式 —— 第一次少写了一层 `dirname`
（`tools` → `ganyu` → `dsh-x4` 是**三**层），报错信息是 `FileNotFoundError` 指向
`ganyu\x4-character-retarget\work\...`，一眼能看出多/少了一层。**改完路径要立刻跑
一个会读这些路径的脚本**（`fit_offline.py` 最便宜），不要等到 Blender 阶段。

## §7 已知问题（与荧共有，非本次引入）

1. **关节残余撕裂**（肩、肘、脚踝）：根因是源骨架与 X4 骨架的脊柱/腿长比例不同。
   "给骨链共享位移"能把数字压下来，但会在手臂和脚踝引入更明显的弯折
   （荧的项目试过并回退，见其文档 §3.12）。取舍：**看起来对 > 数值好看**。
2. **坐姿脚底低 7 cm**：源模型是穿高跟鞋的姿态，X4 的脚骨是平底鞋姿态；
   站姿已对齐（脚底 −0.5 cm），坐姿会略陷。荧是 −9.6 cm。
